# AIによる導入・診断の案内

この公開版はソースを読むAIによるローカル導入補助を想定しています。PCを操作できるAIは実際の確認を行い、チャットのみのAIは本人へ手順を案内します。

## 読む順番

1. [README](../README.md)と[AGENTS](../AGENTS.md)で提供範囲と禁止する迂回を確認する。
2. [モデル準備](model-setup.md)、[動作要件](hardware-requirements.md)、[必須LoRA](required-lora.md)、[利用条件](use-conditions.md)を読む。
3. 開発・修正を伴う場合は[要求](requirements.md)、[設計](design.md)、[実装状況](implementation-plan.md)を確認する。

## 最初に調べること

OSとアーキテクチャ、GPUとVRAM、RAM、導入先とcacheの空き容量、Rust / C++ toolchain、既存ComfyUIの場所・Python・loopback APIを確認します。ドライブ名やユーザー名を開発者の値で決め打ちしません。確認結果にtokenや個人の素材名を混ぜません。

一つの既存ComfyUIを選び、他者のジョブや利用者の変更を保全します。存在しない場合の新規導入は付属セットアップの経路を使います。アプリ用PythonはComfyUIのPythonと分けます。既存の推論環境を自動更新したり、同じPCへ代替の推論サーバーを増やしたりしません。

## 今進められる範囲

ソースの読取り、要件の確認、アプリ用依存の明示的な準備、Rustの構築、CLIとローカル画面の起動確認を進められます。Git cloneの場合は`python -B scripts/check_repository.py`で構造を確認できます。起動には[導入手順](model-setup.md)に従って構築したnative hostが必要です。

**モデル導入・自動取得・H3推論は許諾確認待ちで停止中です。** 別LoRA・LoRAなし・mirror・変更したguardで先へ進めないでください。生成を伴わない確認の成功を、H3の補正成功として報告しません。

## 本人だけが行う操作

主LoRA一つと本人のCivitai APIキーは実際の取得で必須です。本人はセットアップ画面の非表示欄か本人の対話端末で入力します。AIがキーを受け取る必要はありません。HF tokenは必要な場合だけ使い、保存は本人の選択でWindows資格情報マネージャーへ行います。

配布元での同意・申請・認証、課金、権限拡大、公開、復元不能な削除は、会話の承認範囲を確認します。キーやOSの資格情報を抽出して別経路へ移しません。認証成功・ダウンロード成功・用途の許諾は別の事実です。

## 報告すること

確認できたPC条件、構築・起動の結果、停止理由、次に必要な条件を分けて示します。実H3、画質、長尺、12GB / 16GBは未確認のまま成功扱いしません。公開Issueへ動画・job・未加工ログ・キーを添付しません。
